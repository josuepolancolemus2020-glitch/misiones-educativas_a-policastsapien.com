1La frase maestra (apréndela con tus palabras)

«M.E.T.A.S es una aplicación web estática y offline-first,
que se distribuye por tres frentes —web, PWA y APK Android— desde un mismo código,
y usa Supabase como nube para lo único que necesita servidor.»

Cada término de esa frase tiene un significado preciso que debes poder desglosar:

TérminoQué significa aquí
web estáticaEl sitio son archivos HTML, CSS y JavaScript tal cual — no hay un programa corriendo en un servidor que "arme" las páginas. GitHub Pages solo los entrega.
offline-firstLa app se diseñó para funcionar SIN internet primero: los datos viven en el dispositivo (localStorage) y la nube es una copia/extensión, nunca un requisito.
PWAProgressive Web App: la misma página web, pero instalable con ícono propio y capaz de abrir sin conexión gracias a un service worker que guarda una copia local.
APK AndroidLa app nativa para Android. No se reescribió nada: Capacitor envuelve el MISMO código web dentro de una app instalable (id com.policastsapien.metas).
un mismo códigoUn solo repositorio Git. Publicar en la web es git push; llevarlo al APK es npm run sync (copia el código a www/ y Capacitor lo empaqueta).
Supabase"Backend como servicio": una base de datos PostgreSQL en la nube con funciones y reglas de seguridad. Solo se usa para lo que exige servidor: sincronizar entre dispositivos y alimentar el asistente de padres.

2El diagrama maestro: un código, cuatro frentes

Diagrama 1 — Un solo código fuente alimenta tres frentes de distribución; la nube es opcional y complementaria.
Idea clave para defender: los tres frentes NO son tres desarrollos. Es un solo código que se entrega de tres maneras. Por eso una sola persona puede mantener el sistema.

5Cómo viaja un dato (versión panorámica)

El detalle fino es el Módulo 3; aquí basta el recorrido en 5 pasos, que debes poder narrar de memoria:

PasoQué pasa
1. Se generaEl alumno termina una evaluación (o el maestro genera un análisis). El dato nace en el dispositivo.
2. Se guarda localVa a localStorage al instante. Si en ese momento se corta la luz o no hay señal, NADA se pierde.
3. Entra a la colaUna copia entra al outbox (cola de salida) con un identificador único de evento.
4. Sube cuando puedeCon internet, la cola se envía a Supabase por HTTPS. Si se reintenta dos veces, el identificador único evita duplicados.
5. Se consultaEl maestro lo ve en su panel desde cualquier dispositivo; la familia lo consulta en el asistente con su clave.

8Simulacro de interpelación (respuestas modelo)

«¿Dónde está tu servidor?»
No tengo servidor propio, por diseño. El frontend son archivos estáticos servidos por GitHub Pages, y lo único que necesita servidor —sincronizar dispositivos y atender al asistente de padres— lo hace Supabase, un backend-como-servicio sobre PostgreSQL. Menos piezas propias = menos que se cae, menos que mantener y menos que asegurar.
«¿Qué stack usas?»
HTML, CSS y JavaScript puros, sin framework y sin paso de compilación; Capacitor para empaquetar el APK Android; Supabase (PostgreSQL + funciones RPC + RLS) como nube; GitHub Pages con dominio propio como hosting; y service worker para que funcione offline e instalable.
«¿Y si GitHub o Supabase se caen?»
La app sigue funcionando: es offline-first. La PWA tiene copia local del código (service worker) y los datos del usuario viven en su dispositivo; la nube solo sincroniza. Lo pendiente de subir espera en una cola local y sube solo cuando vuelve el servicio — está probado con los cortes de energía reales de Honduras.
«¿Esto es una página web o una app de verdad?»
Las dos cosas, y esa es la gracia: un mismo código se entrega como sitio web, como PWA instalable con ícono propio, y como APK Android firmado (Capacitor). Tres frentes de distribución sin triplicar el desarrollo.
«¿Cuánto te cuesta la infraestructura?»
Prácticamente cero: GitHub Pages es gratuito, Supabase corre en plan Free, y el único gasto fijo es el dominio anual. Eso no es una casualidad: es un requisito de diseño, porque el sistema debe ser sostenible para una escuela pública sin presupuesto.
«¿Y una sola persona mantiene todo esto?»
Sí, y el diseño existe para que eso sea posible: cero frameworks (nada se rompe por dependencias ajenas), cero compilación (depurar es leer el archivo), estructura idéntica en las 55 misiones (arreglar una enseña a arreglar todas), y cada decisión de la nube documentada en su propio archivo SQL comentado.
